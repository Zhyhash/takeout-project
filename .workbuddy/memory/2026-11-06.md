# 2026-11-06

## 支付模块重构：领域类型收拢 + 移除恢复租约 + 网关异常分类

### 第一步：领域语言落地（`Payment/Domain/`，新增）
- `StripeStatus`：7 个 PaymentIntent 状态 + `isTerminal/isSucceeded/isCanceled/matches/isKnown/parseOrNull`。
- `ReconciliationState`：PENDING/COMPLETE/REVIEW + `isRecoverable/code()`，落库值即枚举名。
- `Money`：元→分值对象，构造即校验（取代编排层静态工具 `convertCnyYuanToFen`，该方法保留为兼容入口）。
- `PaymentPolicy`：30 分钟窗口、23h 幂等 TTL、退避 15s/1800s/指数 7、96 次上限、60s 占位时长、`pi_` 前缀。
- 效果：两个 Service 里 9 处 `"succeeded"`、8 处 `"PENDING/REVIEW"`、5 处 `"cny"` 全部收敛；`Integer.valueOf(1)` → `OrderStatusEnum.PAYING`。

### 第二步：移除恢复租约与冗余列（V20261106_1）
- 删 `OrderStripePayment` 的 `leaseToken/leaseUntil/idempotencyExpiresAt/lastError`，保留 `reconciliationState/retryCount/nextRetryAt`。
- `claimAttempt` 改为占位式（`retry_count+1` + `next_retry_at` 前推，CAS 条件 `next_retry_at <= now` 天然互斥）；删 `releaseAttempt`、`finishPaymentAttempt`、`isCreationLeaseValid`（→ `canCreatePaymentIntent`）。
- **关键副作用**：单一 `next_retry_at` 同时承担"占位"与"退避"，首次占位若按 15s 会短于网关最坏耗时（5s+10s+1 次重试）。故加 `PaymentPolicy.ATTEMPT_HOLD=60s`，占位取 `max(退避, 60s)`。
- `recoverOrderPayment` 去掉 try/catch 与重复的 journal/addSuppressed，38 行→24 行。
- 迁移：`V20261106_1__drop_stripe_recovery_lease_columns.sql`（deploy/migrations 同步），`deploy/schema.sql` 同步删列；`V20261105` 不动 checksum。

### 第三步：网关异常分类（用户指出的问题）
- `StripeGatewayException.Kind` 从 `REQUEST_FAILED` 拆为 **`REQUEST_REJECTED`**（Stripe 4xx 明确拒绝：InvalidRequest/Card/Authentication/Permission）与 **`OUTCOME_UNKNOWN`**（ApiConnection 超时、5xx、限流、响应缺字段）。
- 新增 `fromStripeFailure(StripeException)` 分类器；保留 `cause`（原来丢堆栈）、`stripeErrorCode`、`httpStatus`（SDK 的 0 归一化为 null）；消息只含分类/状态码/错误码，不含响应体。
- `recoverOrderPayment` 取消分支：`REQUEST_REJECTED` 时改为 `retrieve` 拉真实状态收场（避免订单卡 PAYING 重试到上限），`OUTCOME_UNKNOWN` 原样抛出。
- `StripePaymentRecoveryTask` 日志增加 kind/stripeCode，不输出 message。
