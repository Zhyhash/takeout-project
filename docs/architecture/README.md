## 阅读约定与准确性边界

- 分层图表示职责；依赖图箭头表示调用方依赖被调用方。业务决策用 `flowchart`，共同事务或提交后交互才用短 `sequenceDiagram`，允许的状态变化用 `stateDiagram-v2`。
- 02～05 按“一句话 → 主流程 → 子流程 → 关键设计 → 异常边界 → 源码定位”阅读。图展示主题内的核心路径，异常表补充未重复画出的失败出口；失败不会继续执行成功路径。
- 源码定位集中列出关键类、方法及可点击路径，以 `../../src/...` 引用，便于在不同检出目录中阅读。
- `FOR UPDATE` 表示显式数据库行锁；普通条件 `UPDATE` 也会竞争数据库写锁。`@Version`、条件状态迁移、Redis Lua 与事务是不同机制，文档分别标明。
- 事务范围按当前 Spring Bean 调用和传播属性描述。提交后回调和调度扫描均单独标明，不归入已经提交的业务事务；配送任务单项 GEO 对账另开 `REQUIRES_NEW`、`REPEATABLE_READ` 事务，并持有任务行锁至 Redis 操作结束。
- 图中只展示已接入当前业务路径的实现。模拟支付、模拟退款、固定配送奖励、未实现的外部支付或真实退款等边界会直接说明。
- 这是当前工作区源码与 SQL 的静态核对，包含已有未提交改动；不宣称已验证线上部署。测试只作行为佐证，不能替代实现。
- 项目专题说明集中在 [`docs` 文档索引](../README.md)；历史重构记录只说明当时变更与验证范围，不替代当前架构章节。与实现有差异时，以当前源码、迁移脚本和可重复测试结果为准。

后续修改相关实现时，应同步复核对应图中的事务边界、状态条件和 SQL。
